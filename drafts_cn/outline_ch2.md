## Section 1: Battery Fundamentals（电池基础）

### 1.1 锂离子电池原理
- 正极/负极/电解液/隔膜四要素
- 充放电过程中的锂离子迁移
- 常见正极材料（LCO/NMC/LFP）及特性差异
- 对SoH的意义：不同化学体系的退化模式不同

### 1.2 SoC 与 SoH —— 正式定义
- SoC = 剩余容量 / 当前最大容量 × 100%
- SoH = 当前最大容量 / 初始额定容量 × 100%
- SoH < 80%/70% → 车载寿命终点
- SOH也可以从内阻角度定义：SoH_R = (R_EOL - R_current) / (R_EOL - R_new)
- 本文采用容量定义

### 1.3 电池老化机理
- **循环老化**：SEI生长、锂析出、电极开裂 → 受DOD/C-rate/温度影响
- **日历老化**：存储期间SEI增厚、电解液分解 → 受温度/SoC存储水平影响
- 老化是**非线性、多因素耦合**的过程 → 难以用简单物理公式描述 → 需要数据驱动方法

## Section 2: SoH Estimation Methods（SoH估计方法综述）

### 2.1 基于模型的方法

#### 2.1.1 电化学模型
- P2D模型（Newman模型）—— 耦合PDE描述锂浓度分布、电化学反应
- 精度高，但计算量过大 → 不适合MCU
- 简化版SPM → 高倍率下精度下降

#### 2.1.2 等效电路模型 + 滤波器
- ECM：Rint / Thevenin / 二阶RC网络
- 配合状态估计算法：EKF / UKF / PF / AEKF → 实时SoH
- 优点：工业成熟、可实时
- 局限：参数漂移（< 老化 → 重新标定）、非线性工况外精度恶化

→ **模型方法的共性缺陷**：依赖显式物理表达，难以捕捉长期老化的复杂非线性

### 2.2 基于数据的方法

#### 2.2.1 经典机器学习
- SVR、GPR、随机森林 → 从数据映射到SoH
- 依赖特征工程的质量

#### 2.2.2 深度学习
- LSTM / BiLSTM → 时域依赖建模 → 公开数据集MAE < 2%
- CNN → 从电压曲线提取空间特征
- 问题：**固定输入尺寸**、**推理成本高**（矩阵乘法）、需要**专用运行时库**（TFLite Micro / X-CUBE-AI）

#### 2.2.3 梯度提升决策树
- LightGBM：直方图分裂 + 叶向生长 → 训练快、精度接近DNN
- 对嵌入式的优势：
  - 推理只做阈值比较和加法，无矩阵运算
  - 输入为定长特征向量 → 天然支持**任意长度原始窗口**
  - 可编译为自包含C代码 → 无外部依赖
- 本论文选型的技术依据

### 2.3 各方法对比总结（表格）

| 方法 | 精度 | 计算量 | 可部署性 | 输入灵活性 |
|------|------|--------|---------|-----------|
| 电化学 | ★★★★★ | ★★★★★ | ✗ | — |
| ECM+EKF | ★★★ | ★★ | ✓ | — |
| DL (BiLSTM) | ★★★★ | ★★★★ | △ | ✗（固定序列）|
| LightGBM | ★★★★ | ★ | ✓ | ✓（定长特征）|

## Section 3: Joint SoC/SoH Estimation（SoC与SoH联合估计）

### 3.1 SoC对SoH的依赖性
- 电池老化后放电特性变化 → 不同SoH = 不同"电池"
- SoC估计需要知道当前可用容量（= SoH × 初始容量）
- SoC估计需要选择与当前老化状态匹配的模型参数
- 如果SoH不准 → SoC一定不准（误差传播）

### 3.2 联合估计的已有工作
- 双卡尔曼滤波（Dual EKF）：同时估计SoC和SoH
- 联合神经网络：共享底层特征 → 多输出头
- 本论文所基于的双模型架构（Alamin提出）：SoH固定 + SoC随动更新

### 3.3 本论文的定位
- 前人联合估计多在仿真层面，未讨论部署
- 本论文聚焦联合架构的**地基**——SoH估计的部署与验证
- Ch1中描述的误差传播实验 → 说明为什么必须先把SoH做准

## Section 4: Edge Computing for Automotive BMS（边缘计算与车载部署）

### 4.1 为什么需要边缘推理
- Cloud推理的问题：延迟/带宽/断网/隐私
- 边缘推理的优势：低延迟、离线可用、数据本地化
- 汽车BMS的特殊要求：ISO 26262功能安全、宽温工作（-40~125°C）、确定性实时

### 4.2 汽车MCU平台
- SPC58系列（ST）：Power Architecture e200z4、120-180MHz、~4MB Flash、~600KB SRAM
- SPC58EC80E5（本论文目标硬件）
- 开发工具链：SPC5Studio IDE → GCC交叉编译 + HAL + 性能profiling

### 4.3 ML部署到MCU的工具链
- TFLite Micro / X-CUBE-AI → 面向神经网络
- EDEN编译器 → 面向决策树/随机森林 → 本论文扩展至LightGBM
- 部署要考虑：模型量化、内存布局、无动态分配

### 4.4 已有部署工作
- Sammartino et al. (2021)：BiLSTM → SPC58 → 固定20样本窗口 → 本论文的基线
- 这是少数走通全程的工作之一 → 但也暴露出固定窗口的局限

## Section 5: Digital Twin for Battery Systems（电池数字孪生）

### 5.1 Digital Twin 概念
- 物理实体 ↔ 虚拟模型的实时双向映射
- 三个要素：物理对象 + 虚拟模型 + 数据连接
- 从产品生命周期管理扩展到电池领域

### 5.2 电池Digital Twin的架构模式
- **纯云端**：数据上传 → 云推理 → 结果返回（有延迟）
- **纯边缘**：本地推理（无法利用全车队数据）
- **云边协同**：边缘推理 + 云端训练/更新 → 本论文采用的模式

### 5.3 已有相关工作
- Li et al.：云端混合模型（ECM+DNN）→ 容量预测
- Wang et al.：电化学模型+实时数据 → 状态估计
- 这些工作重在建模，未讨论车载MCU部署 → 本论文填补的gap

## Section 6: OTA Updates for Automotive Systems（车载OTA更新）

### 6.1 OTA 基本概念
- 远程无线分发软件/固件更新
- 汽车领域：A/B分区、签名验证、回滚机制
- 驱动因素：软件复杂度增长 + 安全漏洞修复需求

### 6.2 汽车OTA的特殊要求
- 不可靠信道下的可靠传输
- 更新过程不能影响行车安全
- 法规/标准：UN R156（软件更新法规）

### 6.3 ML模型OTA的特点
- 更新payload = 模型参数（非可执行代码）
- 树模型：数组（阈值+特征索引+子节点+树根）→ 几十到几百KB
- 触发条件（本论文设计）：SoH下降超过阈值 → 云端重训练SoC模型 → 下发
- 与整车FOTA（Firmware OTA）的关系
