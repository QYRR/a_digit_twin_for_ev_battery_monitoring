# Ch2 Section 3 — SoC与SoH联合估计（完整中文版）

---

## 整体定位

Section 2 将 SoH 估计作为一个独立问题进行了综述。但在真实的 BMS 中，SoH 估计并不孤立——它与 SoC 估计存在深层的耦合关系。本节讨论这种耦合关系、回顾已有的联合估计方法，并明确本论文在联合估计谱系中的位置。这一节直接支撑 Ch1 中提出的双模型架构和"先做好 SoH"的研究优先级。

---

## 3.1 SoC 对 SoH 的依赖性

SoC 估计的任务是回答"电池还剩多少电"。这个看似简单的问题实际上高度依赖于对电池当前健康状态的了解。这种依赖性体现在两个层面：

### 层面一：容量基准

SoC 的公式为 SoC = 剩余容量 / 当前最大可用容量。分母不是电池出厂时的额定容量 C_initial，而是当下的真实最大容量 C_current。二者的关系是：

$$C_{current} = SoH \times C_{initial}$$

因此 SoH 的一个百分点误差，直接转化为 SoC 的分母误差。举例来说，一块额定 100 Ah 的电池，当前真实容量为 85 Ah（SoH=85%），剩余 42.5 Ah。真实 SoC = 42.5 / 85 = 50%。如果 BMS 错误地认为 SoH=90%（仍以 90 Ah 为基准），计算出的 SoC = 42.5 / 90 ≈ 47.2%，存在约 2.8 个百分点的偏差。这种偏差随电池老化逐渐增大。

### 层面二：放电特性漂移

更深层的依赖在于，电池的放电特性曲线本身随老化而改变。如 Section 1.2 所述，老化导致内阻增大、OCV 曲线形态变化和动力学参数偏移。具体表现为：

- 同样的电流脉冲下，老化电池的电压降落（IR drop）更大
- OCV-SoC 关系曲线的形状发生微调——某些 SoC 区间的 OCV 平台可能变得更平坦或更陡峭
- 电池的可用容量受放电倍率（C-rate）的影响程度随老化加剧——一块新电池在 0.5C 和 2C 下的放电容量差可能只有 3%，而一块严重老化的电池这个差距可能扩大到 10% 以上

这些变化意味着：**在不同 SoH 水平上，SoC 估计本质上面对的是不同的系统**。一个基于新电池数据训练的 SoC 模型，用于老化电池时，其精度会因电池物理特性的漂移而持续恶化。

这进一步意味着——在长寿命 BMS 系统中——仅有一个 SoC 模型是不够的。需要一个 SoH 模型来追踪电池的老化状态，并根据当前的 SoH 值来**选择或调整** SoC 估计模型。这正是联合估计方法的基本出发点和本论文所基于的双模型架构的物理逻辑。

## 3.2 已有联合估计方法

文献中已提出了多种将 SoC 和 SoH 协同估计的策略。按估计框架的组织方式，大致可分为三类。

### 3.2.1 基于卡尔曼滤波的双估计器

卡尔曼滤波族是联合估计最经典的工具。基本策略是设立两个并行的估计器，分别处理 SoC（快变量，时间尺度为秒到分钟）和 SoH（慢变量，时间尺度为周到月）：

- **双扩展卡尔曼滤波（Dual EKF）**：两个 EKF 交替运行——一个用当前参数估计值（SoH）来估计状态（SoC），另一个用当前状态估计值来更新参数估计。二者通过共享的电压测量耦合在一起。Plett 的经典工作 [ECM_djEKF] 系统性地建立了这一框架

- **联合扩展卡尔曼滤波（Joint EKF）**：将 SoC 和 SoH 合并为增广状态向量，在一个 EKF 中联合估计。与 Dual EKF 交替执行不同，Joint EKF 在每个时间步同时更新所有状态。实现更简洁，但增广状态向量的协方差矩阵维护成本更高

这些方法的优势是拥有完善的理论基础和工业历史，但本质上受限于 ECM 模型结构——如 2.1.2 节所述，ECM 参数漂移本身要求标定，用漂移后的 ECM 去估计 SoH 是一个循环依赖。

### 3.2.2 基于深度学习的多任务架构

随着深度学习在 SoH 估计中的广泛应用（见 2.2.2 节），研究者开始探索将 SoC 和 SoH 估计统一在一个神经网络框架下：

- **共享底层 + 多输出头**：CNN 或 LSTM 网络提取共享的时序特征表示，然后分出两个独立的输出头——一个回归 SoC，另一个回归 SoH。这种设计的直观动机是 SoC 和 SoH 都依赖于相同的底层电池动力学，共享特征提取可以减少总参数量

- **多任务学习（Multi-task Learning）**：通过联合优化 SoC 和 SoH 的损失函数（通常是两者的加权和），使共享特征层同时学习对两个任务有用的表示。多任务学习在小样本场景下有时能通过任务之间的正则化效应提升泛化性能

然而，这类工作在以下问题上普遍缺乏深入讨论：(1) 多任务网络如何在车载 MCU 上部署；(2) SoH 估计误差如何影响 SoC 输出——多任务架构中两个任务的精度不是独立的，共享层中的误差可以在两个任务间传播

### 3.2.3 级联架构

级联架构将 SoH 估计作为 SoC 估计的前置步骤：首先估计 SoH，然后将 SoH 估计值作为 SoC 模型的输入参数。与多任务并行架构不同，级联架构明确了两个任务之间的**层次关系**——SoH 是基础层，输出不是最终目的，而是 SoC 计算的一个输入。

这种设计有以下优点：
- **模块化**：SoH 模型和 SoC 模型可以各自选用不同的算法——SoH 可能需要强的长期记忆能力（适合树模型或慢更新网络），SoC 需要快速响应瞬态变化（适合滤波器或轻量网络）
- **可维护性**：当电池进入新老化阶段时，理论上只需要更新 SoC 模型（因为老化是一个缓慢变化的偏移，主要影响的是 SoC 的参考基准），SoH 模型可以保持部署时的状态
- **误差追踪**：级联架构使误差传播路径清晰——如果 SoC 估计不准，可以追溯到其原因：是 SoC 模型本身的问题，还是 SoH 输入的偏差？这对故障诊断和系统调试非常重要

本论文所基于的双模型 Digital Twin 架构正属于级联架构这一类别。其关键设计理念是：SoH 模型经过多窗口训练，部署后极少需要更新；SoC 模型以 SoH 为输入，通过 OTA 随电池老化定期更新。这一架构由 Alamin 提出。

## 3.3 已有联合估计工作的共同缺陷

纵观以上三类方法，存在三个共同的、在现有文献中未得到充分解决的问题：

1. **部署论证的缺失**：几乎所有联合估计研究都停留在 MATLAB 或 Python 的离线仿真阶段。作者通常报告 MAE/RMSE 数值，但不讨论模型在车载 MCU 上的推理延迟、内存占用、更新机制等工程实际问题

2. **误差传播分析的空缺**：在联合估计框架中，SoH 的估计误差会传播到 SoC 的估计中。然而已有研究通常只报告两个任务各自的 MAE，不分析两者之间的误差相关性。这使得读者无法评估联合估计方案在"SoH 真的不准"时的鲁棒性——而这恰恰是真实部署中最可能发生的情况

3. **更新策略的缺失**：电池老化是一个长期过程。部署到车辆后的 BMS 模型，在未来数年甚至十年间如何保持准确？现有联合估计工作对此几乎不讨论。级联架构虽然在概念上提供了"SoH 固定、SoC 更新"的可能性，但这一更新在实际中应该如何触发、如何执行、如何保障可靠性——这些问题基本处于未探索状态

## 3.4 本论文在联合估计谱系中的定位

本论文在三个层面上与以上文献背景相联系：

1. **架构层面**：本论文工作在 Alamin 提出的双模型级联架构框架内。论文的 SoH 模型是这一架构的基础层。本文完整实现了该基础层——从模型训练到 MCU 部署——是该架构从概念走向实际部署的关键一步

2. **实验层面**：作者在双模型架构的初步实验中，训练了一个以 SoH 估计值作为输入特征的 SoC 模型。实验观察到了 SoH→SoC 的误差传播效应：SoH 估计在个别样本上的偏差在 SoC 输出中被进一步放大。这个发现——虽然看似"负面"——为联合估计研究提供了一个有价值的观察：**在级联架构中，基础层的精度决定了整个系统的精度上限**。这一观察也为本文聚焦 SoH 的研究优先级提供了实验层面的支撑

3. **工程层面**：本论文处理了联合估计文献中几乎完全缺席的"部署"问题——SoH 模型如何在真实的汽车 MCU 上运行，消耗多少资源。这对未来的联合 SoC/SoH 部署工作提供了一个可参考的基准

## 本节小结（过渡到 Section 4）

本节分析了 SoC 与 SoH 估计的耦合关系，回顾了三大类联合估计方法，并指出了已有工作在部署验证和误差传播分析方面的共同空白。本节的内容解释了为什么本论文将一个"联合估计架构的一部分"——SoH 估计——作为独立的研究对象：不是因为 SoH 可以脱离 SoC 而存在，而是因为在级联架构中，**必须先验证基础层（SoH）足够可靠，上层（SoC）的建设才有意义**。

从本节起，讨论重心从"电池内部发生了什么"和"文献中尝试了哪些方法"转向"在车上怎么部署"和"长期怎么维护"。Section 4 将讨论边缘计算平台和汽车 MCU 部署的技术背景。
