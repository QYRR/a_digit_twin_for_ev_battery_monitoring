## 正文

### 3.6.1 目标硬件

部署目标是 STMicroelectronics 的 SPC58EC80E5 汽车级微控制器。如第2章 Section 4.2 所述，该 MCU 具备双核 Power Architecture e200z420n3 @ 120 MHz、4 MB Flash、608 KB SRAM，支持 ISO 26262 ASIL-B。

部署仅使用 SPC58 单板。电池数据不在板上实时采集——而是将已采集好的测试数据通过串口发送至 MCU，MCU 执行特征提取和模型推理后将结果通过串口返回 PC。这种方式将推理性能的测量与电池物理变量隔离，便于独立评估模型在 MCU 上的计算表现。作者也搭建了完整的 ST BMS 评估套件（SPC58 + 隔离单元 + 模拟前端），该套件在论文中作为硬件环境上下文提及，但不参与本次实验数据采集。

### 3.6.2 软件工具链

部署使用两个软件工具：

**SPC5Studio IDE**：基于 Eclipse 的集成开发环境，集成 GCC Power Architecture 交叉编译器、SPC5 硬件抽象层（HAL）和 Flash 编程工具。用于代码编写、编译和烧录。编译优化级别使用 -O2。

**UDE Starterkit**（Universal Debug Engine，PLS 公司）：用于程序的运行和调试。提供断点、单步执行、内存查看、变量监控等功能。性能分析数据（执行周期计数）通过 UDE 的周期计数器获取。

### 3.6.3 固件集成

SPC58 固件由以下组件构成：

1. **HAL 初始化代码**（SPC5Studio 自动生成）：时钟配置、GPIO 配置、串口初始化
2. **特征提取模块**（手写 C）：接收原始数据数组，输出 10 维特征向量（float32[10]）
3. **模型推理模块**（EDEN 生成）：接收特征向量，遍历树结构，输出 SoH 预测值（float32）
4. **主循环**：从串口读取一批测试数据 → 调用特征提取 → 调用推理 → 串口输出结果 → 等待下一批

所有数据（模型数组、特征提取中间缓冲）均为编译时静态分配，不使用动态内存。栈深度可控——树遍历使用 while 循环而非递归。

### 3.6.4 测试流程

部署后的验证分为两个层面：

**功能正确性验证**：使用若干实际放电窗口数据在 MCU 上运行推理，将输出与 Python 端同一模型的预测值逐位比对。验证结果一致——MCU 上的 C 实现与 Python 端逻辑等价。此验证在部署初期一次性完成，确认代码正确性后不再重复。

**性能测量（CPU 周期数）**：使用随机生成的一组窗口数据（而非实际电池数据）在 MCU 上运行推理，通过 UDE 周期计数器测量执行周期数。使用随机数据而非实际数据的原因是：周期数仅取决于窗口长度和模型结构，与数据的具体数值无关（LightGBM 推理路径由阈值比较决定，但特征提取的计算量与数据值无关）。多次测量的差异微小（< 1%），因此未取平均，直接报告实测值。

**内存测量（Flash / RAM）**：从 SPC5Studio 链接器 map 文件直接读取 Flash 和 RAM 占用。

**模型精度评估**：精度（MAE/MSE）在 Python 训练环境中使用测试集评估，不通过 MCU 逐窗口实测。原因是 MCU 推理输出已被验证与 Python 一致，逐一用 MCU 跑全测试集既不必要也不高效。
