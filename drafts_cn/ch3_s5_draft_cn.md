## 正文

### 3.5.1 编译需求

将 ML 模型部署到 MCU 上，需要的不是 Python pickle 文件，而是一段 C 代码，满足以下约束：

- **自包含**：不依赖任何外部库（无 lightgbm、无 Python runtime、无 OS）
- **无动态分配**：MCU 上通常不允许或不应使用 malloc
- **栈空间友好**：栈深度上限几 KB，不能有深度递归
- **可集成**：一个 .c 文件 + 一个 .h 文件，直接加入 SPC5Studio 工程

对于神经网络，有 TFLite Micro 和 SPC5Studio AI 等工具。对于树模型，EDEN 编译器是本文使用的方案。

### 3.5.2 EDEN 编译器

EDEN（Efficient Decision tree Ensembles）是一个开源编译器，最初由 Daghero 等人开发，面向物联网边缘节点上的随机森林推理 [Eden]。EDEN 将训练好的决策树集合转换为轻量 C 代码，生成紧凑的静态数组表示。

在本论文中，EDEN 被合作者扩展以支持 LightGBM 的梯度提升树格式。主要扩展点包括：

- 支持 LightGBM 的叶向生长（leaf-wise）树结构（与随机森林的层向生长不同）
- 解析 LightGBM 的模型序列化格式（文本或 JSON 格式的 booster dump）
- 生成与 LightGBM 推理逻辑一致的树遍历 C 代码

作者使用该扩展后的 EDEN 编译器完成模型转换，扩展工作由合作者完成。

### 3.5.3 内存布局

EDEN 将 LightGBM 模型中的每棵决策树转换为四个静态 C 数组：

**数组1 —— 分裂阈值 / 叶值（float32[]）**

对每个节点，如果是内部节点，存储该节点的分裂阈值。如果是叶子节点，存储该叶子的预测值（即树的输出贡献值，而非最终的 SoH 估计）。

**数组2 —— 特征索引（uint16[]）**

对内部节点，存储用于分裂的特征编号（0–9，对应10维输入特征的第几维）。对叶子节点，设置为 #Features + 1（即 10），作为叶子标记——推理时遇到此值表示遍历终止。

**数组3 —— 右子节点索引（uint16[]）**

由于节点按前序遍历排列，左子节点隐含在下一个数组位置（cur + 1）。只需显式存储右子节点的索引。对于叶子节点，此值无意义（不会被访问）。

**数组4 —— 树根索引（uint16[]）**

长度为树的数量。第 k 棵树根节点在数组中的起始位置存储于此，使推理循环可以快速遍历每棵树。

### 3.5.4 推理过程

对输入特征向量 x[0..9]，推理按以下伪代码执行：

```
prediction = 0.0
for each tree t:
    idx = root_index[t]          // 从树根开始
    while feature_index[idx] <= 9:  // 不是叶子
        if x[feature_index[idx]] <= threshold[idx]:
            idx = idx + 1         // 左子节点 = 下一位置
        else:
            idx = right_child[idx] // 右子节点 = 显式索引
    prediction += threshold[idx]   // 叶子值 = 树的输出
return prediction
```

整个推理过程不涉及任何函数调用（所有树在同一个循环中处理）、不分配内存、不使用递归。在 SPC58 上，外层循环（for each tree）和内部遍历（while not leaf）被 GCC 编译为紧凑的条件分支和间接跳转序列。

### 3.5.5 模型规模

对于本文使用的最优超参数配置（~400棵树，最大深度8），生成的 C 代码包含：

- 总节点数：每棵树 ≤ 255 个节点，400棵树总计 ≤ 102,000 个节点
- 四个数组的总字节数：约 400–800 KB（取决于实际树的稀疏度，并非所有树都长满到深度8）
- Flash 占用：所有数组声明为 const，存储在 Flash 中（SPC58 有 4 MB Flash，模型占用 < 3%）

编译后的代码由一个 .c 文件（数组定义 + 推理函数）和一个 .h 文件（函数声明）组成。将这两个文件加入 SPC5Studio 工程即可使用。
